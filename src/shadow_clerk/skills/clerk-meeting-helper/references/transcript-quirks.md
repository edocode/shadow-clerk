# 文字起こしの誤認識パターン

shadow-clerk の出力は音声認識なので、固有名詞と専門用語が崩れる。以下は実際に観測された型。
同じ会議の中で同じ語が別々に化けるため、表記の一貫性を頼りにできない点に注意。

## 社名・組織名

崩れ方が最も激しい。**同一会議内で複数の別表記になる。** 観測された崩れ方:

- カタカナの社名が、まったく別の人名や商品名に化ける
- 漢字の社名が同音の別語に化ける(「〜コード」が「〜頃」になるなど)
- 頭字語だけが残る(数文字の社名が2文字のアルファベットになる)
- 「社」「様」が付いたり落ちたりして表記が揺れる

対処: 参加企業の名前を会議冒頭で把握し、用語集(glossary)に登録しておく。
以降は音の近い崩れを同一組織として読む。
`transcript-*.attendees.json` があれば参加者情報が入っていることがある。

## サービス名・製品名

自社や取引先のサービス名は、社名と同じように崩れる。特に:

- **2文字の漢字の固有名詞が、同音の別語に化ける**(これが最も頻出)。
  同じ音を持つ一般的な地名や単語に引き寄せられるため、文脈がないと判別できない
- サービス名を含む複合語(`<サービス名>ID`、`<サービス名>プラス` など)も同様に崩れ、
  前半だけ落ちたり、アルファベットと混ざったりする
- カタカナのサービス名は、音が近い別のカタカナ語に化ける

対処: 用語集に登録した語は、音が近い崩れを同一のものとして読む。
ただし**置換ではなく文脈で判断する**。同音の一般語が本当にその意味で使われている箇所を
書き換えてしまうと逆に読めなくなる。

一般的な技術用語も崩れる。頭字語は文字が落ちたり増えたりし(`OIDC` → `OYDC` / `YDC`)、
カタカナ語は音の近い別のカタカナ語に化ける。

## 一般語

**漢語の熟語が同音の別語になるのが最も多い。** 「工数」が「個数」になる類で、
文として成立してしまうため見落としやすい(「個数がっつり取る」は「工数をがっつり取る」)。

## 観測した対はファイルに貯まる

この文書は**崩れの型**だけを説明している。**実際に観測した「実際の語 ↔ 崩れた表記」の
対は、環境ごとに違うのでファイルに貯める。**

```bash
curl -s "$SHADOW_CLERK/api/misheard"     # 読む
curl -s -X POST "$SHADOW_CLERK/api/misheard" -H 'Content-Type: application/json' \
  -d '{"entries":[{"actual":"遷移","heard":"繊維","note":"推定"}]}'
```

実体は `misheard.tsv`(データディレクトリ)。用語集(`glossary.txt`)が訳語と読みの表
なのに対し、こちらは**読むときに文脈で判断が要る対**を貯める。どちらも transcript には
適用しない。気づくたびに足していくもので、`SKILL.md` の「聞き間違い候補」の節に
読み書きの手順がある。

## 数値・日付

数値は漢数字で書き起こされることがある(「二千二十六年」「十月一日」「九月十四日」)。
また「二千十六年二月」のように、実際とずれた年が混ざることもあるので、
スケジュールに関わる数値は前後の文脈で妥当性を確認する。

**件数などの数値そのものが崩れることもある。** 「一件か七件」のように、
本来ひとつの数値だったものが分かれて記録される場合がある。
数値を根拠に指摘するときは、崩れている可能性を疑い、断定を避ける。

## 文の途切れ

発言の終わりが切れて次の行に続かないことがある(「〜という形」「〜みたいなところで」で終わる)。
1行で意味が取れないときは前後2〜3行をまとめて読む。

## 話者の扱い

`[自分]` = マイク入力(ユーザー)、`[相手]` = スピーカー出力(それ以外の全員)。

- `[相手]` の連続を1人の発言と解釈しない。立場や論調が変わったら話者が交代している
- **出席者が3人以上でも `[相手]` は1つのラベルにまとめられる。** 誰の発言かは判別できない
- 発言を個人名に帰属させない。社名や役割で書く。議事録に個人名を書く場合は、
  推定であることを明記する
- ユーザー自身が `[相手]` として記録される場合もある(会議システムの音声経路による)。
  内容から見て明らかにユーザーの発言なら、タグより内容を信じる

実例: ある会議で「今〇〇さんからもお話ありましたけれども」という `[相手]` の発言があり、
直前の `[相手]` タグの発言が実際にはユーザー本人のものだった。
