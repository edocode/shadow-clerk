# 公開先 — 議事録と Advice を外に出す

**このファイルを読むのは、設定の `publish` が真のときだけ。** 偽なら、議事録も Advice も
外部サービスへ出さない（`ending.md`「公開の可否」）。

## 公開先を決める

`/api/meeting-config/resolve` の値で決まる。

| `publish_to` | 出し先 |
|---|---|
| `artifact`（既定） | Artifact。初回は非公開で作られるので、リンクをユーザーに渡し、共有はユーザーが決める |
| `notion` | `notion_url` のページの**子ページ**として作る（Notion の MCP ツール）。`notion_url` 自体は書き換えない |

`notion` なのに Notion のツールが使えない・`notion_url` に書けないときは、黙って Artifact に
切り替えない。ユーザーに一度だけ伝えて、手元の `.md` だけで続ける。

## 会議中の Advice（`publish_advice` が真のとき）

会議中に参加者みんなで Advice を見られるよう、`advice-<stem>.md` の内容を公開先にも載せる。

- **最初に書いたとき**に公開先を作り、リンクをユーザーに一度だけ伝える
  （「Advice を <リンク> に載せています。参加者に共有してください」）
  - Artifact: `advice-<stem>.md` の Markdown をそのまま公開する（この skill が Markdown での公開を求める）。
    以降は同じファイルパスで公開し直せば同じ URL が更新される
  - Notion: 子ページ「<会議名> — 未解決（<日付>）」を作り、以降はその本文を置き換える
- **更新は Advice を上書きしたときだけ、多くても 2 分に 1 回。** 公開のたびに数秒かかり、
  監視の周回が遅れる。まとめて書き換えた最新の内容を載せればよく、途中の版は要らない
- 載せるのは Advice だけ。`analysis`（確定事実の時系列）とターミナルへの報告は載せない
- 終了時は最後の版を載せたまま残す。議事録を作ったら、その中から Advice のリンクも示す

`publish_advice` が偽なら、Advice は手元のファイル（ダッシュボードの AI分析 タブ）だけに書く。

## 議事録

議事録を作ったら（`ending.md`）、同じ公開先に出す。Notion なら Advice と同じ親の下に
「<会議名> 議事録（<日付>）」の子ページを作る。
