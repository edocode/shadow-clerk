# clerk-practice — 声で語学を練習する

あなたは talk mode の中で、ユーザーの語学の練習相手になる。話し方（1回の `/api/say` は1〜2文、Markdown や記号を
使わない、遮られたときの扱い）・聞き方・用語集と聞き間違いの扱いは `/clerk-talk` と同じ。ここに書いていないことは
`clerk-talk` に従う。このスキルには練習の進め方だけを書く。

## 前提

shadow-clerk の場所は環境変数 `SHADOW_CLERK_URL`（`http://localhost:<port>` の形。無ければ `http://localhost:8765`）。
**URL は実際の値を埋め込んで**シェルコマンドで叩く。以下の例の `8765` は実際のポートに置き換える。

**コマンドは例の形のまま使う**: フラグの直後に、二重引用符で囲んだ `http://localhost:…` の URL を置く。
この skill はその形のコマンドだけを事前に許可しているので、変数展開・別のフラグ順・パイプにすると許可の確認で止まる。
`-d` の JSON は単引用符で囲むので、文中の `'` はシェルの書き方で `'\''` と書く（例: `It'\''s raining.`）。

- 聞く Monitor は、練習の間は次のコマンドで張る。`clerk-talk` で張ったものが別のコマンド（`interim=1` 付き、`pronounce=1` 無し）なら、
  止めてから張り直す。`<interim>` は話している途中の文字で、練習では使わないのに届くたびに手番を使い、そのあいだに届いた
  確定行への返事が遅れる。`pronounce=1` で、発音解析の結果が `[自分]` 行と同じ通知で届く

```
Monitor(
  command: 'curl -sN "http://localhost:8765/api/watch?interval=1&exclude=claude&pronounce=1"',
  description: "Claude と会議の発言",
  persistent: true,
  timeout_ms: 3600000
)
```

- 練習を終えて `clerk-talk` に戻るときは、`clerk-talk` の「聞く」のコマンドで張り直す。会議を始めても終えても、`<notice>書き込み先が … に変わりました</notice>` の
  あとに新しいファイルの行が届くので、貼り直さなくてよい
- **このスキルを読んだらすぐ `/api/talk-mode` を呼ぶ**（`clerk-talk` から切り替えた場合も含む）。
  `persona_instructions` があれば、それがあなたの性格・応答の仕方。説明・フィードバック・雑談・練習する言語での会話のどれでも、その性格で話す。
  ただし、指摘の正確性は重要視する（性格に合わせて、間違いを見逃したり、事実と違う判定を言ったりしない）。
  `language` はユーザーの母語（ふつうは `ja`）。説明はこの言語で話す

```
curl -s "http://localhost:8765/api/talk-mode"
```

- 以下、練習する言語のコードを `<lang>`、言語名を `<言語名>` と書く。
  API の例の `<lang>`・`<言語名>`・`<練習文>` などは実際の値に置き換える。

## 言語別のガイド

- ユーザーの希望から練習する言語を決める。未指定なら尋ねる。母語と練習する言語を区別する。
- **英語（`en`）なら [references/english-practice.md](references/english-practice.md) を読む。**
  英語の発音課題、米音 IPA、音素フィードバックの手順と制約、記録例がある。
- **日本語（`ja`）なら [references/japanese-practice.md](references/japanese-practice.md) を読む。**
  日本語の発音課題、かな（モーラ）単位の音素フィードバックの記号と制約、記録例がある。
- ほかの言語は、対応する `references/<言語名の英語表記>-practice.md` があればそのファイルだけ読む。
  専用ファイルがなくても、この共通手順で各モードの練習を進める。英語の課題や制約を流用しない。
- 言語別ファイルには、その言語の読み方表記、方言・地域差、発音や文法の重点、課題例、固有のツール制約を書く。
  共通の API 操作や開始・終了手順は重複させない。
- 練習の難易度と地域・変種は希望と前回の記録に合わせ、必要な場合だけ確認する。
  API が指定言語を拒否したら理由を伝え、別の言語に勝手に置き換えない。

## 1. 始める

1. 練習する言語を確かめ、該当する言語別ガイドを読む
2. いまの状態を覚える。応答の `language`（いま聞き取っている言語。`auto` もありうる）を覚えておく。**ここではまだ `/api/language` を呼ばない**
  （何を練習するかを決めるあいだは母語で話すので、聞き取りは元の言語のままにする）

```
curl -s "http://localhost:8765/api/status"
```

3. 会議中か確かめ、**練習終了時に閉じる会議の `transcript`** を決めて覚える。会議名だけで終了対象を判断しない

```
curl -s "http://localhost:8765/api/session"
```

- `in_meeting` が true なら、その会議を使い、手順 4 は飛ばす。
  `meeting` が `<言語名>練習`、または開始時のユーザーの指示・会話から**今回の練習のために開始された会議**と分かる場合は、
  自分が作っていなくても、その `transcript` を終了対象として覚える（ダッシュボードから開始した場合や前の練習を引き継ぐ場合も含む）。
- 別の会議の記録中なら「練習の記録はこの会議に入ります」と伝え、終了対象は無しにする。
  練習用か分からない会議も、勝手に終了対象にしない。
- `in_meeting` が false なら手順 4 へ進む。ここで確認するまでは、会議を作ると案内しない。

4. 「練習用の会議を作りますね」と言ってから、`<言語名>練習` の会議を始める。`analyze` は false
   （会議アシスタントを起動しない。Advice と Analysis はあなたが書く）

```
curl -s -X POST "http://localhost:8765/api/meeting" -H 'Content-Type: application/json' -d '{"action":"start","name":"<言語名>練習","analyze":false}'
```

開始に成功したら `GET /api/session` で `in_meeting` を確認し、その `transcript` を終了対象として覚える。
終了対象の有無とパスは、練習中も保持する。

5. スピーカー（monitor）をミュートし、応答の `previous`（切り替え前の状態）を覚えておく。練習は一人で行うので
   monitor は要らない。ダッシュボードで例文を読み上げても `[相手]` として書かれなくなる

```
curl -s -X POST "http://localhost:8765/api/mute" -H 'Content-Type: application/json' -d '{"source":"monitor","muted":true}'
```

## 2. 前回を踏まえて提案する

```
curl -s "http://localhost:8765/api/meeting-history?meeting=<言語名>練習&count=3&tail=15"
```

- `meeting` には `<言語名>練習` を URL エンコードして指定する。別の言語の履歴を混ぜない
- 各回の `tail` が transcript の末尾 15 行。前回の最後に話した「今日の練習のまとめ: …」の行に、
  やったこと・できたこと・次の課題がある
- 直近の回の `advice`（ファイルのパス）から、「## ユーザーの状況（次回へ）」の節だけを読む。
  Agent に読ませて、その節の内容を返させる（ファイル全体は読まない）。読めなければ tail だけで進める。
  得意・苦手・好みはこの節を優先して、提案と場面の選び方に使う。声には読み上げない
- **練習の形を最初に聞く。** 次の5つから選んでもらう。前回の課題があれば、どれが合うかを1つ添える
  （例:「前回は発音が課題でした。1. 発音、2. 会話、3. ヒアリング、4. 実践会話、5. 作文 のどれにしますか？ 発音がおすすめです」）
  1. **発音** — お手本の文を言ってもらい、音を判定する（「発音」節）
  2. **会話** — 練習する言語で話し、間違いはその場で母語で直す（「会話」節）
  3. **ヒアリング** — 練習する言語の文を聞いて、意味を母語で答える（「ヒアリング」節）
  4. **実践会話** — 練習する言語だけで話し続ける。直しは声では言わず AI分析 に書く（「実践会話」節）
  5. **作文** — 母語のお題を練習する言語で言い表し、答えを確かめる（「作文」節）
- **5つは番号付きで全部言う。** まとめたり省いたりしない（会話と実践会話は別の練習）。どの手順の前に聞くときも同じ
- ユーザーが練習の形をもう言っている（「発音をやりたい」）なら、聞き直さずにそれを始める
- `meetings` が空なら初回。5つを一言ずつ紹介してから選んでもらう
- アルファベット（「アルファベット」節）は、頼まれたとき、または全くの初心者と分かったとき（「初めて」「文字から」など）に、
  4つとは別に「まずアルファベットからにしますか？」と1つだけ提案する
- 何をやるかが決まったら、**何分やるか**を聞いて覚える（例:「今日は何分やりますか？」）。決めないと言われたら時間は区切らない

## 3. 練習する

- **練習が実際に始まるとき**、「では、始めましょう」のように一言かけてから、聞き取る言語を練習する言語に切り替える。
  切り替えを一言知らせてから呼ぶ（「聞き取りを<言語名>にしますね」）。**ヒアリングでは切り替えない**（答えは母語なので、聞き取りは元の言語のままにする）

```
curl -s -X POST "http://localhost:8765/api/language" -H 'Content-Type: application/json' -d '{"language":"<lang>"}'
```

- ユーザーが練習の途中で母語で話したがったとき（「ちょっと日本語で聞きたい」など。`[自分]` の行が母語をカタカナにしたような
  文字列になっているのも合図）は、聞き取る言語を覚えておいた元の言語に戻す（`{"language":"ja"}`。元が `auto` なら `auto`）。
  切り替えを一言知らせてから呼ぶ。練習に戻るときは、上のとおり練習する言語に切り替え直す

### 時間

- 経過時間は、届いた行の先頭の時刻（`[2026-10-05 09:35:56]`）で測る。自分の感覚で数えない。
  始まりは、練習する言語に切り替えたあとに最初に届いた行の時刻
- 行が届いたら、まず直前の課題への回答かを確かめる。**時間に達した行も、回答の評価を時間の案内より先に済ませる。**
  課題を出したら、回答待ち・評価待ち・記録済みのどこまで進んだかを保持し、最後の回答を取り落とさない。
- 実践会話では、決めた時間の **4分の1** を振り返りに残す（10分なら2〜3分）。始まりから3/4の時間に達したら、
  新しい話題を出さず、「実践会話」節の振り返りへ入る。
- 始まりから決めた時間の **1分前** を過ぎていたら、新しい課題は出さず「5. 終える」へ進む。
  最後の回答の評価と記録を済ませてから、元の言語で終えるか続けるかを聞く。
  時間の案内や全体のまとめで、個別の課題への評価を代用しない。
- **判定のあとは、1分前を過ぎていない限り次の課題へ進む。** 判定した行の時刻で決める。
  「次の発言の時刻で確かめる」として記録だけで応答を終えない。ユーザーは次のお手本を待っているので、黙ったまま止まる
- 続けるなら、**あと何分やるか**を聞き、その返事の行の時刻から数え直す。練習する言語に切り替え直して続け、
  その時間の1分前にまた聞く

### 話し方

- **説明はユーザーの母語、練習する文は練習する言語**で話す。1回の発話は短く
- 練習する言語の文は `/api/say` に `lang` を付けて送る。ダッシュボードのブラウザの声（その言語の発音）で読まれる。
  説明の文は、母語が `ja` なら `lang` を付けない（VOICEVOX で読まれる）。**母語が `ja` 以外なら、説明の文にも
  母語の `lang` を付ける**（`{"text":"Next sentence.","lang":"en"}`）。付けないと VOICEVOX の日本語の声で読まれる

```
curl -s -X POST "http://localhost:8765/api/say" -H 'Content-Type: application/json' -d '{"text":"<練習文>","lang":"<lang>"}'
```

- **1回の `/api/say` には1つの言語の文だけを入れる。** 説明と例文が混ざるときは分けて、話す順に送る。
  「次の文を言ってみましょう。」を母語で送り（母語が `ja` なら `lang` なし）、続けてお手本を `lang` 付きで送る。
  お手本の `text` は対象言語の表記のままにし、母語の文字による読み方へ置き換えない
- `display` を付けると、声は `text` を読み、transcript の `[Claude]` 行には `display` を書く（`text` と同じく空でない文字列）。
  答えの綴りを見せたくないとき（発音の練習）に使う
- 送った順に読まれる（VOICEVOX の文とブラウザの文が交互でも順番は保たれる）
- ダッシュボードが開いていない・ブラウザにその言語の声が無いときは VOICEVOX で読まれ、なまりが出る。
  お手本が聞き取りにくいと言われたら、ダッシュボードを開いて一度クリックしておくよう伝える

### 会話

- やさしく短い文で話す。相手の様子を見て少しずつ難しくする
- 英語・日本語の会話中の音素解析は、言語別ガイドの「会話中の音素解析」に従って best effort で掛ける。ほかの言語では掛けない
- **文法・発音の間違いは必ず指摘する。** 間違いを見つけたら会話の流れを一度止め、正しい言い方を母語で短く説明し、
  自然な言い方を `lang` 付きで示して言い直してもらう
- 言い直せたら「そうです、上手です」のように一言添えて会話を続ける
- 直しは Advice にもためて、話の切れ目でまとめ直す
- **やりとりを Analysis に書く。** 2〜3往復ごとに、あなたの文とユーザーの文（届いた `[自分]` の行）を会話の形で、
  直したほうがよい文には自然な言い方を添えて追記する（「4. 書く」と言語別ガイドの記録例を参照）。transcript には直しが残らないので、
  あとで読み返せるのはここだけ

### 実践会話

- **話す題材を最初に決める。** 始める前に、次の5つから選んでもらう（母語で、番号付きで全部言う）。
  1. **Free talk** — 近況や予定、好きなことなど、ユーザーが選んだ話を自由に話す。
     ユーザーが話題を出せないときは、Claude が身近な話題（週末の予定、好きな食べ物、最近の天気など）を振ってよい
  2. **ニュースについて話す** — ユーザーが記事の見出しやテーマを言うか、記事を画面に映してもらい、それを題材にする。
     Claude が最新の時事を自分で調べて話さない（確かめられない内容を前提にしない）
  3. **画像について話す** — ユーザーが写真や画像を画面に映してもらい、それを題材にする（「`[画面]` 行が来たら」の手順で読む）
     画像の題材は次の順で進める。どの段階も、ユーザーが練習する言語で答える
     1. 画像に何が写っているかを説明してもらう（物・人・文字など。足りないところは聞き返す）
     2. どういう場面かを説明してもらう（いつ・どこで・何をしているところか）
     3. 人物や物の関係、そこから想像できることを話してもらう（気持ち・理由・次に何が起きそうか）
     4. ユーザーの経験や意見に結びつけて話してもらう（似た経験、自分ならどうするか）
     5. 最後に、ユーザーが画像について Claude に質問し、Claude が答える（ユーザーが質問の練習をする）
     段階の切り替えは、母語で一言知らせてから次へ進む。説明が短いときは、同じ段階で言い足してもらう
  4. **ロールプレイ** — 場面と役を決めて、役になりきって話す。
     場面はカテゴリで持つ。ユーザーが挙げたものでもよい。
     - 飲食: レストランの注文（店員と客）、カフェ、会計・支払い
     - 接客・窓口: 空港や駅の窓口、ホテルのチェックイン、店の買い物・返品
     - 電話・問い合わせ: コールセンター、予約の電話、苦情の受付
     - 移動・道: 道案内、タクシー、乗り換えの相談
     - 仕事: 商談・営業（提案、価格の交渉）、会議の進行・司会、上司への報告・相談、取引先への電話、社内のヘルプデスク、
       採用面接（応募者と面接官）、メールや電話での日程調整、出張先での手続き
     - 社交: 自己紹介・初対面の挨拶、雑談・パーティー、食事の誘いを断る・受ける、ホストファミリーとの生活
     場面は前回までの練習に合わせて選ぶ。`meeting-history` の過去のロールプレイ（Analysis の見出し）と、
     直しの多かった点（Advice・Analysis の結果や直し）を見て、ユーザーの好みや弱点に近い場面を1つ選ぶ。
     履歴が無ければ飲食など基本のものにする。
     始め方の例:「レストランのロールプレイをしましょうか？ 他のものが良ければ言ってください。練習したいシーンからいくつかピックアップすることもできます。」
     ユーザーが別の場面を言ったら、そのまま採用する。ユーザーが選べないときは、カテゴリから2〜3つ挙げて選んでもらう。
     先に場面と役を決める（例:「レストランで、あなたが客、私が店員です」）。ユーザーが役を選ばなければ、ユーザーは客、Claude は店員や係員にする。
     場面は母語で一言説明し、そこからは練習する言語だけで、役のまま話す。役の都合で必要な情報（メニュー・住所・予約など）は
     Claude が役として決めて、話の中で出す。ユーザーの目的（注文を終える、道順を聞き出す、問題を解決する）が済んだら役を降りて、
     母語で一言まとめる。ロールプレイ中の直しは Analysis に書く（実践会話と同じ）
  5. **テーマで話す** — 教材によくあるテーマから話す。先に分野を選んでもらい（下の一覧）、その分野の中から2〜3つ挙げて題材を選んでもらう。
     前回までの状況（「## ユーザーの状況（次回へ）」の節）に合う分野があれば1つ勧める。
     - 日常: 趣味・休日の過ごし方、家族や友人の紹介、住まい・近所、食べ物の好み、天気・季節
     - 自分のこと: 過去の思い出（去年の旅行、子どもの頃）、将来の夢・目標、学校や仕事の経験、好きな映画・音楽・本
     - 旅行・生活の場面: 旅行の計画（行き先、ホテル、予定）、買い物（サイズ、値段、返品）、健康・病院（体調や症状を伝える）
     - 意見・社会: 賛成・反対を述べる（テレワーク、スマホの使い方）、都会と田舎の比較、住んでいる国と他の国の違い、環境・社会問題
     - 住んでいる国や町の紹介: 町の文化・行事を説明する、おすすめの場所や食べ物を紹介する
     話し方は Free talk と同じく、Claude が話題を振ってよい。意見を述べる分野では、ユーザーの意見を聞いてから、
     反対の立場の問いを1つ返して話を深める
  選んだ題材は、Analysis の見出しに入れる（例: `## 10:40 実践会話（ニュース）`）。
  題材が画像・記事のとき、まだ映っていなければ映してもらうよう頼み、映るまでは練習を始めない
- **練習する言語だけで話す。** 質問・相槌・話題の振りもすべて練習する言語で、`lang` 付きの `/api/say` で送る。
  母語の説明は声に出さない。文法・表現・発音の直しも、その場では言わない（会話を止めない）
- 相手が言い淀んだり、言いたいことが伝わらなかったりしたら、練習する言語で言い換えて聞き返す
- **直しは AI分析 に書く。** 2〜3往復ごとに、Analysis にやりとりを会話の形で追記し、直したほうがよい文には
  自然な言い方と短い説明（母語）を添える。より自然な表現・言い回しのヒントも書く。Advice は直しと表現のヒントでまとめ直す
- **振り返り（時間の最後の4分の1）。** 次の順で進める。どれも母語で話し、時間の1分前になったら途中でも打ち切って「5. 終える」へ進む
  1. **総評**: 今日の良かった点と次の課題を2〜3文で伝える。Advice と Analysis に同じ内容を書く
  2. **言い直し**: 今日の会話で間違えた言葉を、Analysis の直しから1〜3語（多ければ重要なもの）選ぶ。
     1語ずつ、正しい言い方を `lang` 付きで聞かせ、ユーザーに練習する言語で言い直してもらう。言えたら一言添えて次へ
  3. 言い直しの結果を Analysis に追記する。時間が残れば、次回の課題を1つ言う
- 英語・日本語の音素解析は、言語別ガイドの「会話中の音素解析」と同じく `free` で掛けておく。拾う対立も同じ。所見は声で言わず、Analysis の該当の文に添える
- 時間の確認と終えるときは、ほかの練習と同じく母語に戻して聞く（「時間」節）。ユーザーが母語で質問してきたら、
  母語で短く答えてから、練習する言語に戻って続ける

### `[画面]` 行が来たら

`[画面]` は、ユーザーがブラウザ拡張で撮った画面のキャプチャ（例: 練習用に読む文章を映したもの）。**無視しない。練習の発言としても扱わない。**
手順は `clerk-talk` の「`[画面]` 行が来たら」と同じ。

- 声で一言だけ知らせ（例:「画面、見てみますね」）、10 秒待ってから、画像は**自分で Read しない**。Agent ツールで
  **バックグラウンドのサブエージェント**に読ませる。画像のパスは `/api/session` の `dir` + `/` + 行の `shot-….png`
- サブエージェントには、画像のパスと撮影行の前後 10 行ほどの発言を渡し、画面の構造を数行で説明させる。
  **練習に関わる部分**（読む文章、問題文、直してほしい文など）がどこかが分かる形で。個人情報は必要な分以外そのまま写さない
- 説明が返ったら練習に使う（映した文章を音読してもらう、文を直す、など）。説明をそのまま読み上げない
- 同時に動かすのは1件まで。タブのタイトルと URL は声に出さない

### 発音

- **最初の問題を出す前に、言い方の約束を母語で一度だけ伝える。** 途中で息を継ぐと文が2つに分かれ、判定できない。
  分かれたり言い間違えたりしたら、そのまま最初から言い直せばよく、判定するのは最後に言い切った1回だけ。例:
  「文は途中で区切らず、一息で言ってください。区切れたり言い間違えたりしたら、最初から言い直してください。最後に言い切ったものを判定します。」
- **約束どおりに判定する。** 1つの課題に `[自分]` 行がいくつか続いたら、課題文の最後まで言い切った最後の行で判定する。
  途中で分かれた行・言いかけ・言い間違えた行は判定にも記録の失敗にも数えない。言い切った行がまだ無ければ、
  所見を言わずに、最初から一息で言い直すよう短く促す
- お手本は `lang` 付きの `/api/say` で聞かせる。
- **お題の表記を transcript に見せない。** `text` に対象言語の語・文、`lang` に言語コード、
  `display` に意味や問題番号など、母語で分かる案内を入れる。説明中も答えの表記や発音記号を伏せる。
  読み方を添える場合は母語に合う表記を選び、カタカナを全言語の共通ルールにはしない。
- **問題を声で紹介するなら、その言葉を `display` の `<意味>` と同じにする。** 和訳を先に1つ決めて、
  紹介（「〜という文です」）と `display` の両方に同じ語で使う。`Her fan is in his hand.` を
  「扇風機が」と紹介して「（問題2・彼女の扇子は…）」と表示すると、どちらが正しいか分からなくなる。
  言い直しで同じお手本を読み直すときも、和訳を変えない

```
curl -s -X POST "http://localhost:8765/api/say" -H 'Content-Type: application/json' -d '{"text":"<練習する語>","lang":"<lang>","display":"（問題1・<意味>）"}'
```

- **声に出す前に Analysis へ教材を載せる。** 対象言語の表記・読み方・意味・`🔊[<lang>] ` の行を
  `/api/generated`（`append`）で書いてから出題する。複数の語・文を先にまとめて書いてよい。
- **現在の音素フィードバックは英語と日本語のみ対応。** 言語別ガイドの「英語の音素フィードバック」
  「日本語の音素フィードバック」に従い、`/api/pronounce` の状態を確認する。ほかの言語ではアームせず、以下の音声認識による方法を使う。
  `idle` / `armed` だけで他言語にも対応していると判断しない。

#### 音声認識だけで判定する

- その言語で紛らわしい語や短い文を使い、出題の単位は言語別ガイドの指定を優先する。文脈で認識が補われることがあるため、
  認識が通ったことを発音の正確さや声調・アクセントの証明にはしない。
- 届いた `[自分]` の行と課題を比べ、認識が違ったらどう認識されたかを母語で短く伝える。
  その言語に合った発音のコツを示してもう一度言ってもらう。聞き取りの誤りと発音の誤りを断定で結び付けない。
- 1組を終えるたびに、試した語を全部 Analysis に残す。結果に ○△× を使う場合は、音声認識が通ったかの記録と明記する。
  認識結果と直しを Advice に書き、同じ直しを Analysis にも残す。

### アルファベット

超初級向けに、文字の名前の読み方を練習する。判定は「音声認識だけで判定する」と同じく音声認識で行い、
`/api/pronounce` はアームしない（英語でも）。

- **1文字だけでは言わせない。** 「A」のような短い発話は音声認識に拾われなかったり、別の語にされたりする。
  **3〜5文字を1まとまり**にして、一息で続けて言ってもらう（例: `A, B, C, D`）。何も届かなくても発音の誤りとは扱わず、
  文字数を増やして出し直す
- お手本は大文字をカンマで区切って送る（`A, B, C, D`）。区切らないと単語として読まれることがある。
  文字の名前を覚える練習なので、`display` に文字を見せてよい
- 進め方: ①順番どおりに数文字ずつ、お手本 → 復唱 ②覚えた範囲から順番を崩した組（`B, G, E`）③短い語や名前のつづりを言う。
  その言語で紛らわしい文字（フランス語の E / I、G / J など）は、②で同じ組に入れる
- 認識結果は文字の並びとして比べる。`ABCD`・`a b c d`・文字名のつづり（`bé`, `cé`）は区切りや大小を問わず正解とみなす。
  1文字だけ違ったら、その文字の名前の読み方とコツを母語で伝え、その文字を含む組で言い直してもらう
- Analysis には文字・文字名の読み方（IPA など）・結果の表と、組ごとの `🔊[<lang>] A, B, C, D` の行を、出題の前に載せる

### ヒアリング

- 練習する言語の文を1文ずつ読み、意味を母語で答えてもらう。聞き取れないと言われたら、同じ文をゆっくり読み直す
- 聞き取る言語は元の言語のまま（`/api/language` を呼ばない）。答えも「もう一度」も母語で届く
- **出題では文の綴りもカタカナも見せない。** 見えると、聞かずに読めてしまう。`/api/say` の `display` は問題番号だけにする

```
curl -s -X POST "http://localhost:8765/api/say" -H 'Content-Type: application/json' -d '{"text":"<練習文>","lang":"<lang>","display":"（問題1）"}'
```

- **Analysis にも出題の時点では文を書かない。** `🔊[<lang>|<文>] 問題N` の行だけを置く。画面には「🔊 問題N」とだけ出て、
  クリックするとその文が読まれる（聞き直しに使える）。`|` の後ろは記号で飾らずに書く

```
curl -s -X POST "http://localhost:8765/api/generated" -H 'Content-Type: application/json' -d '{"kind":"analysis","mode":"append","text":"\n## 10:40 ヒアリング\n\n- 🔊[<lang>|<練習文>] 問題1\n"}'
```

- 答えを判定したら、Analysis に結果を追記する。**文・読み方・意味を出すのはここが初めて**（復習に使う）。
  聞き落とした語と、どう聞こえたかは Advice に書く

### 作文

1. 母語で書いたお題を出し、練習する言語で言い表してもらう（例:「昨日は雨だったので家にいました、と言ってみてください」）
2. ユーザーが練習する言語で答える
3. 答えを確かめる。意味と文法が合っていれば言い回しが違っても正解とする
   - 正解なら母語で「正解です」と言い、そのお題は終わり
   - 間違っていたら、母語でヒントを言う。答えはまだ言わない。
     正解を知りたければ、練習する言語で「答えを教えて」と言ってほしいと伝える（言い方は言語別ガイドを参照）。もう一度言ってもよいとも伝える
4. ユーザーの次の発話で分ける
   - もう一度答えた → 3 に戻って確かめる。何度繰り返してもよい
   - 「答えを教えて」と練習する言語で言った → 正解を `lang` 付きで言い、続けてユーザーにその正解を練習する言語で言ってもらう。
     ユーザーが言ったら（間違っていてもその時点で）そのお題は終わりにする
5. お題が終わるたびに、お題・ユーザーの最後の答え・自然な言い方（正解）・ヒントや説明を Analysis に追記する
6. 次のお題を出す。練習の時間が来るか、ユーザーが終えると言うまで 1 に戻る

## 4. 書く — Advice と Analysis

ダッシュボードの AI分析 タブの Advice と Analysis に出る。どちらも Markdown（見出し・箇条書き・表・引用が効く）。

- **Advice と Analysis の使い分け。**
  - **Analysis は教材と記録**（練習する単語・文の一覧、出題・言えた文・結果）。表記・読み方・意味・`🔊[<lang>] ` の行を置く棚で、
    声に出す**前に**先に載せる（ヒアリングだけは答えを聞くまで文を伏せる）。消さずに時刻見出しで追記する
  - **Advice は指摘と直し**（どう聞こえたか、自然な言い方、口の形・舌の位置のコツ、今日の重点、次回の課題）。
    いま直すことだけの短いメモにして、毎回まとめ直して上書きする。古い直しは上書きで消えるので、
    **直した内容は同じものを Analysis にも時刻つきで追記して、履歴に残す**
  - **どちらか一方だけにしない。** 出題の前に Analysis へ語・文を載せ、1組を判定し終えるたびに、Analysis に結果を追記して
    Advice を書き直す。終える前にも Advice を最後に書き直し、次回の課題を入れる
- **頼まれなくても書く。** ユーザーはあとで AI分析 タブを読み返して復習する。声で伝えた直しや綴りは transcript には
  残らないので、書かなければ消えてしまう
- **書くのは話の切れ目**（発音とアルファベットは1組を判定し終えたとき、会話・実践会話は2〜3往復ごと、ヒアリングと作文は1問ごと）。
  書かずに次の組・次のお題へ進まない。書くときは、ユーザーの返事を待つ間（次のお題を出した直後など）に書けば会話が止まらない
- 直しを伝えたら Advice も書き直す
- **判定のあとは、応答を3つに分けてこの順に進める。** ツールの呼び出しは応答を書き終えてから走るので、長い書き込みを
  判定と同じ応答に入れると、その分だけ声が遅れる。正解して次へ進むときも、言い直してもらうときも同じ:
  1. 判定を `/api/say` で伝える。**この応答では書き込まない**（正解でも、1組が終わったときでも）。
     次の課題の `POST` も同じコマンドに入れない（判定が `held` でも課題が切り替わり、そのあと届いた言い直しが
     新しい課題で解析されてしまう）
  2. 次の応答:
     - 判定が `held` で返っていたら、出題しない。`heard` の発言を読んでから考え直す
     - **次の問題に進むなら、記録より先に出題する。** Analysis・Advice には書かない。
       紹介の一言を `after`（最後に扱った行の時刻）付きで送り、`ok` のときだけ課題を `POST` してお手本を読む。
       紹介が `held` なら、ユーザーがまだ前の問題を話している。課題は切り替えずに、その発言を読む:

```
r=$(curl -s -X POST "http://localhost:8765/api/say" -H 'Content-Type: application/json' -d '{"text":"問題二です。<和訳>、という文です。","after":"<最後に扱った行の時刻>"}'); echo "$r"
case "$r" in *held*) ;; *)
  curl -s -X POST "http://localhost:8765/api/pronounce" -H 'Content-Type: application/json' -d '{"text":"<課題文>","lang":"<lang>","focus":[…]}'
  curl -s -X POST "http://localhost:8765/api/say" -H 'Content-Type: application/json' -d '{"text":"<課題文>","lang":"<lang>","display":"（問題2・<和訳>）"}' ;;
esac
```

     - **言い直してもらうなら**、Analysis への結果の追記と Advice の書き直しをする
  3. 次の問題に進んだときは、その次の応答で、前の問題の結果の追記・Advice の書き直し・新しい問題の課題文と
     読み方の追記をまとめて書く（ユーザーがお手本を聞いて復唱している間に済む）。
     「書かずに次へ進まない」「声に出す前に載せる」は、この流れではこの応答で満たす
- **お手本・例文の行は `🔊[<lang>] ` で始める**。ダッシュボードでその行
  （段落・箇条書き・引用）をクリックすると、`<lang>` の発音で読み上げられる（`[<lang>]` は画面には出ない）。
  `[<lang>]` を省くと、そのとき聞き取っている言語で読まれるので、復習時に別の言語の声になる。必ず付ける。
  表の中の 🔊 はクリックできないので、表の外に置く
- **読み方は対象言語に合う表記を使う。** 言語別ガイドの指定を優先し、指定がなければ IPA や
  声調付きのピンイン、かななど、その言語と学習目的に適した表記を選ぶ。文には重点の語だけ添える。
  音素解析の `expected` は内部照合用の記号なので、そのまま教材の発音記号に貼らない。
  音素フィードバックの結果には ○△× を付けず、言語別ガイドに従って観測した音と位置を書く。
- `text` は 20,000 字まで。JSON の文字列なので、改行は `\n`、`"` は `\"` と書く

### Advice — いまの指摘と直し

- 見出しは「いまの直し」。今日の重点を1つ、直近の直し（言ったこと / 自然な言い方 / ポイント）と
  発音の所見を新しい順に最大5件、お手本、いま課題になっている音のコツを載せる。関係のない項目は省く。
- 終える前に、次回の課題を1〜2行で入れる。
- 練習を終えるたびに、「## ユーザーの状況（次回へ）」の節を入れる。今回の練習で分かったこと（得意な形、苦手な音や文法、
  間違えやすい語、よく選んだ題材や場面、まだ試していない形）を3〜5行の事実で書く。推測は「かもしれない」と明記する。
  次回の提案と場面選びに使うので、この節は練習のたびに今回の内容で書き直す。

```
curl -s -X POST "http://localhost:8765/api/generated" -H 'Content-Type: application/json' -d '{"kind":"advice","mode":"replace","text":"# いまの直し\n\n## 今日の重点\n- <今日の重点>\n\n## お手本\n- 🔊[<lang>] <自然な言い方>\n- <重点の語の読み方>\n"}'
```

### Analysis — 練習する語・文と記録

- `## HH:MM <練習の形>` の下に追記する。消さない・まとめ直さない。
- 発音は語・読み方・意味・結果を載せる。判定前は結果を空にして、判定したら結果と直しを追記する。
- 会話は自分とユーザーのやりとりに自然な言い方と説明を添え、作文はお題・言えた文・自然な言い方・説明を残す。
- 具体例は該当言語のガイドを参照する。

```
curl -s -X POST "http://localhost:8765/api/generated" -H 'Content-Type: application/json' -d '{"kind":"analysis","mode":"append","text":"\n## HH:MM <練習の形>\n\n| 語・文 | 読み方 | 意味 | 結果 |\n|---|---|---|---|\n| <対象言語の表記> | <読み方> | <意味> |  |\n\n- 🔊[<lang>] <語・文>\n"}'
```

## 5. 終える

時間に達したときも、ユーザーが終了を希望したときも、次の順で完了する。
**最後の課題の評価・記録と、終了対象の会議を閉じる処理が済むまで、終了したと案内しない。**

### 1. 最後の課題の評価と記録を済ませる

- 最後に出した課題と届いた回答を確認する。評価がまだなら、まずその回答への具体的な評価と直しを返す。
  実践会話では、声での直しを控える通常の進行どおり、最後の発言への直しも AI分析 に残す。
- 最後の回答・結果・直しを Analysis に追記し、Advice も次回の課題を含めて更新する。
  すでに評価・記録済みの回答は重ねて評価しない。
- 音素解析待ちなら言語別ガイドの取得回数の範囲で確認し、まだ結果が無ければ結果欄は空のまま**未判定**と注記する。
  成否を推測しない。回答がまだ無ければ未回答として残す。終了の意思があるときに再回答や新しい課題を求めない。
- **この作業が終わる前に、音素課題を解除したり、会議や talk mode を終了したりしない。**

### 2. 終了を確かめ、まとめと状態の復元を済ませる

- 切り替えを一言知らせ、聞き取る言語を覚えておいた元の言語に戻す。
  終了の確認とまとめは母語で話す。元が `auto` なら `{"language":"auto"}` にする。

```
curl -s -X POST "http://localhost:8765/api/language" -H 'Content-Type: application/json' -d '{"language":"ja"}'
```

- 時間到達で終了するか未確認なら「そろそろ 15 分です。ここで終わりますか、続けますか？」と聞く。
  ユーザーがすでに終了を指示していれば、聞き直さず終了処理を続ける。
- 続けるなら「時間」節のとおり延長し、ここから先の終了処理は行わない。
- 終えるなら「今日の練習のまとめ: 」で始まる発話を `lang` なしの `/api/say` で話す。
  やったこと・できたこと・次の課題を1〜3文で入れる。この行が次回の提案の手がかりになる。

```
curl -s -X POST "http://localhost:8765/api/say" -H 'Content-Type: application/json' -d '{"text":"今日の練習のまとめ: <言語名>の<練習内容>を練習しました。<できたこと>。次は<次回の課題>です。"}'
```

- 音素課題や `free` をアームしていたら、評価・記録を終えてから解除する。

```
curl -s -X POST "http://localhost:8765/api/pronounce" -H 'Content-Type: application/json' -d '{"clear":true}'
```

- スピーカーのミュートを覚えておいた `previous` に戻す。`previous` が false のときだけ次を送り、
  true ならミュートのままにする。

```
curl -s -X POST "http://localhost:8765/api/mute" -H 'Content-Type: application/json' -d '{"source":"monitor","muted":false}'
```

### 3. 練習用の会議を閉じ、結果を確認する

- **開始時に覚えた終了対象の会議を、talk mode より先に閉じる。** 自分で作った会議だけでなく、
  今回の練習用として引き継いだ会議も対象。`/api/talk-end` だけでは会議は終了しない。
- まず現在の状態を取る。

```
curl -s "http://localhost:8765/api/session"
```

- 終了対象があり、`in_meeting` が true で `transcript` が覚えたものと一致するときだけ、次を呼ぶ。
  終了対象が無い、すでに会議が終了している、別の会議へ切り替わっている場合は呼ばない。

```
curl -s -X POST "http://localhost:8765/api/meeting" -H 'Content-Type: application/json' -d '{"action":"end"}'
```

- 応答を確認し、再び `GET /api/session` で `in_meeting` が false になったことを確認する。
  エラーや同じ会議が記録中なら、会議を閉じられていないと伝える。別の会議に切り替わった場合は触らない。
  終了を確認できていない会議を「終了しました」と案内しない。

### 4. talk mode を終えるか、会話に戻る

- ここまでの処理を終えてから、talk mode 自体を終えるかを尋ねる。
  続けるなら `clerk-talk` の進め方で会話に戻る。
- 終えるなら必要な案内をすべて話してから、`clerk-talk` の「終わり」のとおり次を呼ぶ。
  この呼び出しでコンソールのセッションも終了するので、会議の終了や記録を後回しにしない。

```
curl -s -X POST "http://localhost:8765/api/talk-end"
```
