# ダッシュボードからの音声デバイス選択とレベル表示

作成日: 2026-08-10

## 背景

2026-08-10 の会議中、shadow-clerk が「自分」の発話を 1 行も記録しない事象が発生した。原因は PipeWire のデフォルト入力が内蔵の Ryzen Digital Microphone（常時 RMS 約 2760・クレストファクタ 1.3 の定常ハムしか出さない実質死んだデバイス）になっていたことだった。ユーザーは Shokz Loop110 のヘッドセットに向かって話しており、会議アプリはそちらを明示指定していた。

shadow-clerk のマイクは `device=None`（PortAudio の `default`）で OS のデフォルト入力を辿るため、デフォルトが壊れたデバイスに落ちると無言で壊れる。ストリーム自体は正常にフレームを供給し続けるので、先に実装したフレーム途絶ウォッチドッグには引っかからず、ダッシュボードも `use_mic: true` を表示し続ける。

この設計は 2 つの問題に対応する。

1. **選べない**: shadow-clerk が使うデバイスを OS の設定を触らずに指定できない
2. **気付けない**: 意図しないデバイスを掴んでいても、ダッシュボード上で判別できない

## ゴールと非ゴール

**ゴール**

- ダッシュボードからマイク／スピーカー（モニター）を指定できる
- 入力レベルが常時見え、意図しないデバイスや無音状態にその場で気付ける
- 指定したデバイスが消えている間も録音を止めない

**非ゴール**

- OS のデフォルトデバイスを書き換える機能（`wpctl set-default` 相当）は作らない。OS の状態を書き換える上に PipeWire / PulseAudio / Windows で実装が分かれるため
- 異常時の通知やログ警告（デスクトップ通知、`logger.warning` の発行等）は作らない。ダッシュボード上の表示（バーの警告色）にとどめ、気付くかどうかは人間に委ねる

## 設定

`DEFAULT_CONFIG`（`_daemon_constants.py`）に 2 キーを追加する。値は**デバイス名**であり、番号ではない。デバイス番号は起動ごとに変わり、稼働中にも移動するため同一性の判定に使えない（`CLAUDE.md` の Known Pitfalls 参照）。

```yaml
mic_device: null       # null = 自動（OS のデフォルト入力に追従）
monitor_device: null   # null = 自動（デフォルト Sink の .monitor）
```

`_save_config`（`_daemon_dashboard_ops_config.py`）は `DEFAULT_CONFIG` のキーを走査して保存するため、保存側の変更は不要。

CLI の `--mic` / `--monitor`（番号指定）は互換性のため残し、指定時は config より優先する（CLI 引数の慣習に従う）。

## デバイス解決とフォールバック

`_daemon_audio.py` の `resolve_mic_device` / `resolve_monitor_device` を「設定名 → 実デバイス」の解決に拡張する。戻り値は `AudioDevice`（`index` と `name`）のままとし、フォールバックしたかどうかは呼び出し側が設定値と `AudioDevice.name` を比較して判定する。

解決順序:

1. 設定に名前があり、その名前のデバイスが一覧に存在する → それを開く
2. 設定に名前があるが一覧にない → **自動にフォールバック**して開く。設定値は書き換えない
3. 設定が `null` → 従来通り自動（mic は PortAudio の `default`、monitor はデフォルト Sink の `.monitor`）

`_watch_streams`（`_daemon_recorder_capture.py`）の 2 秒ごとのチェックに「設定値 ≠ 現在開いているデバイス名」の判定を追加する。既存の `changed_sink()` と同じ位置に置くため、検知後の張り替え経路（全ストリームを閉じる → `refresh_device_list()` → 名前で再解決 → 再オープン）は完全に再利用できる。

この 1 つの仕組みが 3 つの動作を同時に満たす。

- ユーザーがパネルで選び直す → 次のチェックで張り替わる（**デーモン再起動は不要**、音の欠落は約 1 秒）
- 指定デバイスが消える → 次のチェックで自動にフォールバックする
- 指定デバイスが戻る → 次のチェックで指定デバイスに復帰する

設定値の読み取りは `load_config()` を使う（mtime キャッシュがあるため 2 秒ごとの呼び出しでも実質無コスト）。`_api_configured` の教訓どおり `__init__` でキャッシュしない。

## レベル計測

`_CaptureStream._callback` で、1 秒窓の RMS 合計・サンプル数・ピークを蓄積する。480 サンプルの numpy 演算なので、毎秒 33 回の呼び出しでも負荷は無視できる。

`_CaptureStream.level()` が直近 1 秒の値を返して窓をリセットする。返す値は 3 つ:

- `rms`: 平均音量
- `peak`: ピーク
- `crest`: `peak / rms`（クレストファクタ）。`rms` が微小（1 未満）のときは 0 を返す。無音時に 0 除算で値が発散するのを避けるため

クレストファクタを出すのは、今回の切り分けで決め手になった指標だからである。音声なら 3〜10 以上、定常ノイズなら 1〜2 になり、「デバイスは開けているがノイズしか来ていない」状態を数値ひとつで判別できる。実測値は内蔵マイク 1.3 / Shokz 49.4 だった。

## 配信経路

`/api/status` のポーリングは 10 秒間隔（`_daemon_dashboard_js_panels.py:182`）でメーターには遅すぎる。一方 `FileWatcher.run()`（`_daemon_log_buffer.py:126`）は既に 1 秒周期で回り、SSE で `transcript` / `log` / `ptt` などを配信している。

`FileWatcher._poll()` に `level` イベントを追加する。追加のスレッドもポーリング経路も不要。

```json
{"mic": {"rms": 34.3, "peak": 1799, "crest": 52.4, "device": "alsa_input.usb-Shokz_...", "fallback": false},
 "monitor": {"rms": 0.0, "peak": 0, "crest": 0.0, "device": "alsa_output...monitor", "fallback": false}}
```

`fallback` は「設定でデバイスを指定しているが、それが見つからず自動で代替中」を表す。デバイスが開けていない系統は `null` を返す。

1Hz + ピークホールドは VU メーターとしては粗いが、「マイクが生きているか」の判断には十分であり、既存ループに相乗りできる利点が上回る。

## UI

**ヘッダー（常時表示）**

既存のミュートボタン（🎤 / 🔊、`_daemon_dashboard_html.py` の `btnMuteMic` / `btnMuteMonitor`）の隣に細いレベルバーを 2 本置く。常時表示なので、設定パネルを開かなくても異常に気付ける。

- バーの長さは RMS を対数スケールで表示する
- **定常ノイズ警告**: 直近 10 回（= 10 秒）の `level` イベントがすべて「`rms` >= 100 かつ `crest` < 2」を満たしたらバーを警告色にする。`rms` の下限を課すのは、無音時に `crest` が 0 になって誤検知するのを防ぐため。判定はブラウザ側で行い、サーバは生の値だけを送る
- `fallback` が真のときはボタンを警告色にし、tooltip に「指定デバイスが見つからないため自動で代替中」と出す

**設定パネル**

セレクトボックスを 2 つ追加する。先頭の選択肢は「自動（OS のデフォルト）」（= `null`）。その下に検出されたデバイスを列挙する。隣に「一覧を更新」ボタンを置く。

**デバイス一覧 API**

`GET /api/audio-devices` を新設し、`_daemon_dashboard_base.py` のルーティングに追加する。

```json
{"mic": [{"name": "...", "label": "..."}],
 "monitor": [{"name": "...", "label": "..."}],
 "updated_at": 1786500000.0}
```

**この API の制約**: PortAudio のデバイス一覧は `Pa_Initialize` 時点のキャッシュであり、ブラウザの要求ごとに再列挙はできない（`refresh_device_list()` は開いている全ストリームを破棄するため）。したがって一覧は監視スレッドが保持するスナップショットを返す。スナップショットは次の 2 つの契機で更新される。

1. 再接続のたび（デバイス変更・フレーム途絶・Sink 変更の張り替え時）
2. 「一覧を更新」ボタンによる明示要求

明示要求は監視スレッドに再列挙を依頼するフラグを立て、監視スレッドが張り替えサイクルを 1 回実行する。約 1 秒の音欠落を伴うため、自動ではなくユーザーの明示操作に限る。ボタンにはその旨を tooltip で示す。

`label` は人間が読める表示名とする。PipeWire のノード名（`alsa_input.usb-Shokz_Shokz_Loop110_...mono-fallback`）は一意だが読みにくいため、`sd.query_devices()` の情報から整形する。`name` が実際のキーであり、`label` は表示専用。

## i18n

新規の文字列（セレクトのラベル、「自動（OS のデフォルト）」、フォールバック時の tooltip、「一覧を更新」）は `_i18n_ja.py` / `_i18n_en.py` に追加し、`t()` 経由で参照する。ダッシュボード側は既存の `{{i18n:key}}` プレースホルダと `/*I18N_JSON*/` の仕組みに従う。

## エラー処理

- 指定デバイスが開けない（一覧にはあるが `PortAudioError`）→ 既存の `_open_capture` のリトライ（1 回）を経て自動にフォールバック
- 自動でも開けない → 既存の `degraded` 経路で 30 秒ごとに再試行
- `/api/audio-devices` がスナップショット未生成の状態で呼ばれた（起動直後）→ 空配列と `updated_at: null` を返し、UI は「検出中」と表示する

## 検証

テストフレームワークがないプロジェクトのため、検証はスクリプトで行う（既存の watchdog 検証スクリプトと同じ方式）。

1. **名前解決とフォールバック**: 存在しない名前を設定 → 自動にフォールバックすること、名前が一覧に現れたら復帰すること
2. **設定変更の反映**: 稼働中に config を書き換え → 2 秒以内に張り替わり、フレームが再開すること
3. **レベル計測**: ダミー波形（無音・正弦波・定常ノイズ）を流し、クレストファクタが期待値（無音は 0、正弦波は約 1.41、ノイズは 1〜2、音声相当のバースト波形は 3 以上）になること
4. **実機確認**: ダッシュボードのセレクトを切り替えてマイクが張り替わること、レベルバーが動くこと
